# v0.5.1 — Lifecycle lookup enforcement hotfix

Release date: 2026-08-28

## Why this patch exists

A fresh Codex review of the merged v0.5.0 change found two concrete follow-up defects:

1. MCP `get_local_rule` could still read the legacy local-rule projection directly, so a lifecycle record marked `abolished`, `superseded`, or `pending_reverification` could be bypassed.
2. Runtime `__version__` was `0.5.0` while `pyproject.toml` still declared distribution version `0.4.1`.

## Fixed

- Route MCP `get_local_rule` through the canonical local-rule lifecycle selector before returning compatibility fields.
- Fail closed for pending, inactive, ambiguous, malformed, overlapping, or historically indeterminate lifecycle state.
- Return lifecycle metadata (`official_identifier`, `legal_status`, lifecycle status, legal-event dates) with a successful current lookup.
- Keep historical lookup fail-closed while NTPC `effective_from` remains unverified.
- Synchronize runtime and Python distribution metadata at `0.5.1`.
- Add MCP regressions for current lookup, historical unknown-effective lookup, and `pending_reverification` bypass prevention.
- Add a regression asserting `pyproject.toml` version equals runtime `__version__`.

## Scope unchanged

This patch does not enable Taipei or Taoyuan and does not include the three central-law pending snapshots tracked in issue #16. The remaining PR C / PR D work in issue #18 stays deferred.
